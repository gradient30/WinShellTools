# DevShellTools 稳定性、安全性与性能硬化设计

## 1. 背景

DevShellTools 由 PowerShell 模块和 Tauri 2 桌面端 Studio 组成。现有版本已经具备以下基础：

- 分类脚本编辑、函数级 CRUD、安装/卸载和配置包同步。
- PowerShell AST 语法解析、静态安全检查、隔离进程试运行。
- 命令分类缓存、批量解析、后台文件 IO 和逐字节运行时同步。
- 73 个 Rust 单元测试与 26 个验收测试，现有功能测试全部通过。

评估发现的主要问题集中在安全边界、崩溃恢复、并发写入、AI 执行链路和工程门禁，而不是基础功能缺失。当前最危险的组合是“不可信脚本或元数据进入工作区，经字符串拼接生成 PowerShell，再由模块加载器执行”。

## 2. 意图与成功标准

目标是在不破坏现有编辑、安装、AI 助手和配置包工作流的前提下，分阶段消除高风险问题，并提高可恢复性与可验证性。

成功标准：

1. 不可信配置元数据和 AI 输出不能直接变成未确认的任意 PowerShell 执行。
2. 核心文件写入在进程崩溃或并发保存后仍能恢复到一组完整、一致的版本。
3. API Key 不再以可直接读取的明文长期存储。
4. AI 响应具备真实增量输出、可取消、可超时和明确成本上限。
5. 编辑保存不等待后台运行时同步，连续保存不会启动无限并发复制。
6. 现有 99 个测试继续通过，新增安全与并发回归测试；前端生产构建通过。
7. 格式、Clippy、测试、前端构建和模板一致性成为可重复执行的发布门禁。

## 3. 非目标

- 不把 Studio 设计成可安全执行任意陌生人代码的通用沙箱。
- 不增加管理员权限要求，不修改系统级环境变量。
- 不改变现有公共命令的核心使用方式，除非该方式本身违反安全红线。
- 不引入在线服务依赖；离线构建能力继续保留。
- 不在本轮实现跨机器加密密钥同步或云端密钥托管。
- 不以大规模 UI 重构拖延安全修复。

## 4. 反目标

- 为了更强安全检查而频繁误伤正常的 PowerShell 脚本。
- 为了原子写入而让用户保存时等待整棵模块目录复制完成。
- 为了流式 UI 而重复解析或显示两份最终消息。
- 在迁移 API Key、会话或生成文件时先删除旧数据。
- 在错误恢复时自动覆盖用户唯一可用的文件。
- 把后台同步失败静默当作成功。

## 5. 约束

- Windows PowerShell 5.1 与 PowerShell 7 必须继续兼容。
- Studio 只能修改当前用户文档目录和用户 Profile，不得提权。
- 构建必须支持 `CARGO_NET_OFFLINE=true`；新增依赖应尽量少且已在本地缓存。
- Tauri 前后端随同一个 EXE 发布，可以进行协同协议升级，但仍需兼容现有工作区文件。
- 工作区可能被网盘、备份软件或其他编辑器同时访问。
- 安全检查是“防止意外和降低供应链风险”的护栏，不等同于操作系统级隔离。

## 6. 已选实现路线

采纳“渐进式硬化”路线。每个阶段先增加回归测试，再替换实现；每阶段结束都运行全部后端测试和前端构建。

考虑过但未选择的路线：

- 架构重构优先：长期结构更好，但会把高风险修复与大范围移动混在一起。
- Windows Sandbox/AppContainer 优先：隔离更强，但部署、兼容和测试成本过高。

## 7. P0：阻断高风险执行链

### 7.1 安全生成 PowerShell

新增统一的 PowerShell 字面量编码模块：

- 普通数据字符串使用单引号字面量，内部单引号按 PowerShell 规则双写。
- 分类标识符必须匹配 `^[a-z][a-z0-9]*$`，用于标识符前再次校验。
- 标题、描述、别名、帮助文本、示例和命令展示名只作为数据编码。
- 不再使用仅转义双引号的 `escape_ps_str` 生成可执行脚本。
- 模板占位符缺失返回结构化错误，不使用 `panic!`。

分类元数据在解析后立即校验。配置包预览和正式写入都执行相同校验，避免“预览通过、写入阶段采用不同规则”。

### 7.2 AST 安全策略

保留快速文本预检，但最终判定使用 PowerShell AST 提取的调用结构：

- 识别 `git`、`git.exe` 及其全局参数后的实际子命令和参数。
- 识别 `SetEnvironmentVariable` 的实际作用域参数。
- 识别同一次 `Stop-Process` 调用是否具备 `-Confirm` 或允许的 `SupportsShouldProcess` 上下文。
- 识别同一次 `Remove-Item` 是否同时具有 `-Recurse` 和 `-Force`。
- 对无法静态确定目标命令的动态执行形式默认拒绝，包括 `Invoke-Expression`、`& $variable` 和动态脚本块执行。

`/danger` 继续只影响当前 AI 会话；管理页保存和配置包导入不受影响。拒绝结果必须包含规则名、命令名和可操作说明。

### 7.3 示例试运行改为显式操作

- AI 代码插入不再自动执行 `.EXAMPLE`。
- 插入成功后显示“运行示例自测”操作，用户点击前展示将要执行的首行命令和目标文件。
- 自测进程设置硬超时、输出上限和工作目录；超时会终止子进程。
- 自测失败不回滚已插入代码，但保留现有明确警告。
- 普通函数的“测试”按钮仍可使用，并同样受超时与输出上限保护。

### 7.4 修正内置命令红线

- `gpp` 在调用 git 前拒绝 `-f`、`--force`、`--force-with-lease` 及所有 `--force*` 形式。
- 移除 `lpr clean-user` 的主动写用户环境变量行为；只检测并提示用户显式处理。
- 根模块和 Studio 模板同步修改，Help 与 README 保持一致。
- 增加实际 PowerShell 调用测试，确保危险参数在启动 git 前失败。

## 8. P1：稳定性、密钥和输入边界

### 8.1 工作区路径收口

新增工作区相对路径类型，所有读写入口统一：

- 拒绝绝对路径、盘符路径、UNC、`..`、ADS 冒号和其他路径前缀。
- 将反斜杠统一为 `/`，规范化后必须仍位于工作区根目录。
- 对必须存在的父目录做 canonicalize 检查，防止 junction/symlink 逃逸。
- 分类文件名只允许单个 `.ps1` 文件名。
- 会话 ID、AI Profile ID 和日志文件名只允许安全字符集。

删除前端未使用的高风险通用命令：`read_workspace_file`、`write_workspace_file`、`delete_workspace_file`。

### 8.2 缩小 Tauri 权限面

- 移除未使用的 `tauri-plugin-fs` 及全部 `fs:*` capability。
- 设置 `withGlobalTauri = false`。
- 移除生产依赖中的 `devtools` feature；开发构建仍可通过 Tauri 调试能力调试。
- CSP 移除 `script-src 'unsafe-inline'`；如开发模式确有需要，使用独立开发配置。

### 8.3 API Key 使用 Windows DPAPI

- 使用当前 Windows 用户的 DPAPI 加密 Key。
- 新文件使用带版本头的二进制格式，并通过原子替换写入。
- 首次读取旧明文 Key 时，先成功写入加密文件，再删除旧文件。
- 加密迁移失败时继续读取旧 Key，保证 AI 功能可用，同时返回明确警告，不删除旧数据。
- Key 只在请求期间解密，不进入日志、配置包、会话或错误信息。
- 掩码按 Unicode 字符处理，避免非法 UTF-8 边界导致进程中止。

### 8.4 事务式工作区写入

新增统一文件事务设施：

1. 为所有目标文件生成同卷临时文件。
2. 写入内容、刷盘并校验。
3. 将现有文件移动到备份目录。
4. 使用替换语义安装全部新文件。
5. 全部成功后清理备份；任一步失败则按逆序回滚。
6. 在 `.studio/transactions/` 写入恢复日志；应用启动时检测未完成事务。

PowerShell 模块依赖固定文件名，因此不采用“版本目录 + 指针”切换。通过备份、恢复日志和启动恢复把跨文件不可原子性降到可恢复范围。

生成文件按 `Help.ps1`、`DevShellTools.psm1`、`DevShellTools.psd1` 的顺序安装，清单最后生效，避免新导出列表先于实现文件出现。

### 8.5 单实例运行时同步

- 取消每次编辑直接 `std::thread::spawn`。
- 使用一个有界后台 worker 和“最新版本优先”的合并队列。
- 编辑请求在本地文件事务成功、缓存完成更新后即可返回。
- 同步状态通过事件展示为“等待同步 / 同步中 / 已同步 / 失败”。
- 新请求到达时合并尚未开始的旧请求，正在执行的同步完成后只再执行最新版本。
- 失败不影响编辑结果，但保留错误和可重试操作。

### 8.6 子进程和 AI 超时

- PowerShell 解析、校验、试运行、安装和运行时探测统一使用带超时的进程运行器。
- 捕获 stdout/stderr 时设置单流上限，超过上限返回截断错误，防止内存失控。
- 超时先终止子进程，必要时强制结束，再返回可诊断错误。
- AI 请求设置连接超时、等待响应超时和流空闲超时。
- 取消令牌按请求创建；`ai_cancel_chat` 仅取消当前活动请求，不使用全局布尔位。
- AI HTTP Client 复用连接池，不再每次请求重新创建。

## 9. P2：性能、可维护性和工程门禁

### 9.1 真正流式 AI 输出

- 使用 Tauri Channel 把 `start`、`delta`、`reasoning`、`done`、`validation` 事件推送到前端。
- 前端收到首个 delta 即追加到当前助手消息，无需等待完整响应。
- 完整响应结束后在后端执行代码块提取、语法和安全校验，再发送 `validation`。
- 取消、超时或网络错误发送 terminal error 事件并清理 loading 状态。
- 最终落盘只在流结束后执行一次，避免每个 delta 重写会话文件。

### 9.2 上下文和成本预算

- 后端计算粗略 token 预算，同时在 UI 展示当前会话大小级别。
- 超过预算时优先保留 system prompt 和最近消息，较旧消息替换为摘要式省略提示。
- 工作区命令清单设置最大字符数。
- 不再自动将 `max_tokens` 提升到 65,536。
- 仅保留一次必要的协议兼容重试；因输出长度不足时返回可操作错误，由用户确认提高预算。
- Profile 保存时校验 URL、温度、最大输出和模型字段。
- 非环回公网端点默认必须使用 HTTPS；本机和私有网络 HTTP 地址允许但明确提示风险。

### 9.3 有边界的架构拆分

- `commands.rs` 按 workspace、AI、sessions、tools 拆分为子模块，保留现有命令名。
- `ChatPanel.svelte` 拆出代码块、消息列表和输入/命令联想组件；纯状态转换移入可单测 TypeScript 模块。
- 不在本轮重写 UI 设计或状态管理框架。

### 9.4 模板与质量门禁

- Studio 模板继续作为 1.0.5 模块源。
- 根模块保留 1.0.4 发行版语义，但通过规范化比较检查共享实现是否漂移。
- 新增平台无关验证脚本，执行：
  - `cargo fmt --check`
  - `cargo clippy --all-targets -- -D warnings`
  - Rust 单元与验收测试
  - `pnpm build`
  - 前端纯逻辑测试
  - 模板/根模块规范化一致性检查

修复现有 Clippy、格式、Svelte 可访问性和响应式初始化警告。依赖审计作为独立可联网检查，不阻塞离线构建，但在发布清单中必须记录结果。

## 10. 迁移与兼容

- 旧 `.studio/ai_keys/{id}.txt` 在成功加密迁移前保持可读。
- 旧 AI 配置、会话和配置包字段使用默认值反序列化。
- 会话保存格式增加版本字段时保持旧文件可读。
- 删除命令只从 Tauri handler 和前端 API 移除；工作区已有文件不受影响。
- P0/P1/P2 可分别提交和回退，但发布产物只在全部阶段测试通过后生成。
- 任何安全策略变化都提供具体违规文本，避免只显示“未知错误”。

## 11. 稳定性保障

### 11.1 失败策略

- 安全校验失败：拒绝写入，不破坏原文件。
- 本地事务失败：回滚，保留备份并显示恢复路径。
- 后台运行时同步失败：编辑成功，状态标记失败，可手动重试。
- 密钥加密失败：继续兼容旧读取路径，不阻断现有 AI 使用。
- AI 流超时或取消：保留已接收文本的会话快照，状态明确结束。

### 11.2 可观察性

- 为解析、保存、生成、同步、AI 首字和 AI 完成增加耗时日志。
- 日志不记录 API Key、Authorization 或完整用户提示词。
- 运行时同步和事务状态可在工具箱中查看。

### 11.3 恢复

- 启动时自动检查未完成事务。
- 自动恢复仅处理 Studio 自己创建且有完整日志的事务。
- 无法确定安全性时保留现场并提示用户恢复备份，不自动覆盖。

## 12. 测试设计

### P0

- 元数据包含 `$()`、反引号、引号、换行和分号时生成脚本仍只包含数据。
- 配置包导入后的生成文件通过 PowerShell 语法解析，且没有不可信额外调用。
- `git -c x=y reset --hard`、别名、变量拼接和动态执行被拒绝。
- `/danger` 只放宽当前会话。
- AI 插入不再自动执行示例；显式试运行可超时结束。
- `gpp --force` 和 `gpp -f` 在调用 git 前失败。
- `lpr` 不再写用户级环境变量。

### P1

- 路径类型拒绝绝对路径、`..`、盘符、UNC、ADS 和符号链接逃逸。
- 加密 Key 写入、读取和旧明文迁移成功；失败时旧读取仍可用。
- 模拟中途写入失败可完整回滚。
- 应用启动可恢复或安全保留未完成事务。
- 连续 100 次编辑只产生一个排队同步和一个最新版本同步。
- 所有子进程超时后可终止并返回错误。
- 并发 AI 请求不会互相清除取消标记。

### P2

- Channel 首字在完整响应前到达前端。
- 取消、超时和网络错误都进入明确终态。
- 超长会话按预算裁剪且保留最近消息。
- 前端纯逻辑测试覆盖命令联想、会话恢复选择和代码块状态。
- 根模块/模板比较能检测真实实现漂移。
- 全量验证脚本可在干净环境执行。

## 13. 分阶段验收

每一阶段必须同时满足：

- 不新增现有功能回归。
- 所有旧测试通过。
- 新风险测试先失败，再通过。
- `pnpm build` 成功。
- 工作区没有非预期变更。

P0 完成后不得存在已知“导入数据直接生成可执行代码”路径。P1 完成后并发保存和崩溃恢复测试必须通过。P2 完成后格式、Clippy、全量测试、前端构建和一致性检查共同构成发布门禁。

## 14. 价值

- 安全价值：阻断配置包和 AI 输出到本机代码执行的直接链路，降低密钥泄露和不可逆破坏风险。
- 稳定性价值：把多线程覆盖写入改为可恢复事务，降低崩溃、断电和连续编辑造成的文件损坏。
- 性能价值：编辑不等待运行时复制，AI 首字更早可见，长会话成本受控。
- 维护价值：路径、策略、编码和进程执行均只有一个受测入口，减少模板与后端规则漂移。
- 用户价值：安全失败有明确反馈和恢复路径，安全增强不以功能不可用为代价。

## 15. 待确认

本设计不新增管理员权限，不实现 Windows Sandbox，也不改变现有命令名。示例试运行从默认自动执行改为显式用户操作，这是一项有意为之的安全默认值变更。

以下事项由实现者决定，不需要用户逐项选择：

- 本轮开发期间不修改版本号；全部阶段验证通过并准备正式发布时，再按仓库现有版本清单统一升级。
- DPAPI 通过最小化的 Windows API 绑定实现，不引入常驻服务或网络密钥库。
- CI 以仓库内平台无关验证脚本为事实来源；托管流水线只需调用该脚本。
- 模板规范化检查忽略已知的元数据和版本差异，只比较共享实现语义。
